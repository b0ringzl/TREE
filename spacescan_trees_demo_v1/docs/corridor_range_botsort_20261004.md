# 走廊照片范围与 BoT-SORT 对比（2026-10-04）

## 已上线的操作方式

在正式 `/corridor` 页面选择或读取 VMMS 文件夹后，按有效全景图的自然文件名顺序编号。

- 新读取文件夹默认选第 1–300 张；不足 300 张时使用可用数量，至少需两张。
- 可填写起始张数、结束张数或采样张数。每次最多 300 张，默认连续读取，不跳帧。
- “最前一段、上一段、下一段、最后一段”便于切换。最后一段可选择文件夹末尾的完整 300 张；不足时自动缩短。
- 界面显示所选区间首尾文件名。张数是文件序号，不等于米数；没有定位记录时不声称每帧相距 1 米。
- 历史任务恢复其原来的范围，不会将旧的 136 张结果篡改为 300 张。
- 高级选项仍可设置跳帧间隔。范围切换按钮恢复连续读取。

范围逻辑集中在 `static/corridor-range.js`，同时用于浏览器与 Node 边界测试。输入修改有 350 ms 防抖；开始处理前会再次规范化参数。API 采用零基 `start_index`，界面采用一基张数。

## 预览布局

缩略图按钮采用包含边框和内边距的固定 236 px 宽度；图片在其 220 px 内容区内等比显示。工作区、轨迹卡和长文件名允许收缩或换行。缩略条保留横向滚动，整页不应横向溢出；全景图不使用 `cover` 强行裁切。

## BoT-SORT + ReID 离线试验

本次不是只修改名称：使用已安装 Ultralytics 8.4.53 的真实 `BOTSORT`，每个固定透视视角独立跟踪。接入缓存的 CLIP ViT-B/32 外观向量，并在原始全景展开图上运行 sparse optical-flow 摄像机运动补偿。

这不是专用树木 ReID 训练模型。没有训练、下载新权重、改动树种概率或切换生产模型。BoT-SORT 的 ID 仅作为匹配建议，仍需通过球面几何、初始外观锚点、近期外观与图库一致性检查；近似并列匹配被拒绝，避免强行串联两棵树。没有真实检测的预测框不写入识别结果。

完整观测归属分区也一致，并非只有数量相同。旧 Tree 1、2、4 的七组已知不应连接的图片对，两种方案均未错误连接。两种方案均没有同一轨迹同一帧的重复分配。

结论：本次试验未证明 BoT-SORT 改善身份关联，因此正式方案继续使用 `corridor-geometry-gallery-v4-20261003`。候选另有透视渲染和光流开销；报告时间口径不相同，不能据此计算公平的端到端速度比。候选数不是树种准确率，也不能代替 IDF1/HOTA 或完整人工实例标注评估。
