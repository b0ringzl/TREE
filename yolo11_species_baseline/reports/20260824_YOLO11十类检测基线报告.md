# YOLO11 十类树种检测基线报告

日期：2026-08-24

分支：`codex/hk-image-resnet50-10class`

正式实验：`yolo11s_10class_v2`

## 1. 结论

已完成 YOLO11 的独立环境配置、数据转换、GPU 训练、训练监控、独立测试和整图推理。
正式版本相比第一次试跑有明显提升，但测试召回率只有 0.2064，尚不满足实际应用要求。
因此本次结果证明“技术链路可运行”，不能证明“十类整图识别已经可靠”。

## 2. 环境与模型

- Python 3.10.20
- Ultralytics 8.4.127
- PyTorch 2.11.0 + CUDA 12.8
- NVIDIA GeForce RTX 4090 D（24 GB）
- COCO 预训练 `yolo11s.pt`，检测头从 80 类调整为 10 类
- 输入 640 × 640，batch size 48，AdamW，初始学习率 0.001
- 最多 80 轮，patience 20；实际训练 56 轮后早停
- 最佳验证结果出现在第 36 轮
- 正式训练耗时 277.4 秒（约 4.62 分钟）

YOLO 任务是“从完整图像中定位目标树并判断树种”，比对已经裁好的树木图块做分类多了
一个目标定位环节，因此不能把检测 mAP 与 ResNet50 分类准确率直接横向比较。

## 3. 数据与隔离检查

复用 `hk_web_resnet50_10class_v2` 的固定划分，但使用完整原图及其原始 YOLO 标注框；
多边形标注转换为紧致外接矩形。数据文件以硬链接方式落盘，未复制 1059 份原图。

| 划分 | 图像数 | 目标框数 | 来源 |
|---|---:|---:|---|
| 训练 | 952 | 1445 | 710 张网络图像 + 242 张香港街景 |
| 验证 | 52 | 54 | 仅香港街景 |
| 测试 | 55 | 57 | 仅香港街景 |

验收结果：10 类均进入三个划分；香港同组样本无跨划分泄漏；图像内容哈希无跨划分重复；
测试发生在训练完成之后；测试权重 SHA-256 与保存的最佳权重一致。

## 4. 正式测试结果

| 指标 | 结果 |
|---|---:|
| Precision | 0.6583 |
| Recall | 0.2064 |
| mAP@0.50 | 0.2579 |
| mAP@0.50:0.95 | 0.1125 |

| 置信度 0.25 下输出框数 | 34 |
| 单张推理耗时（模型统计） | 约 2.7 ms |

测试集各类 mAP@0.50:0.95：

单类 AP 不稳定，不能据此做可靠的树种间优劣结论。

## 5. 第一次试跑与修正

第一次试跑 `yolo11s_10class_v1` 使用 AdamW 初始学习率 0.01，整图预测明显向
`Araucaria` 单类坍缩，测试 mAP@0.50 为 0.0872、mAP@0.50:0.95 为 0.0394。
正式版将初始学习率降为 0.001并减弱增强后，两项指标分别提升至 0.2579 和 0.1125，
约为第一次试跑的 2.96 倍和 2.86 倍。第一次试跑仅作为调参诊断，不作为最终基线。

## 6. 可视化检查与风险

训练损失整体下降，验证 mAP 上升，说明网络确实学到了部分定位与分类能力。预测图中
`Acacia mangium`、`Araucaria` 和 `Areca catechu` 已出现有效识别，但 0.25 置信度下仅
24/55 张测试图有输出，并且 34 个输出中 `Araucaria` 18 个、`Areca catechu` 13 个、
`Acacia mangium` 3 个，其余七类没有输出，仍存在严重类别偏置和漏检。

主要限制不是 CUDA 或训练流程，而是当前数据语义不完全适合整图检测：

1. 原标注主要标出“目标树”，同一图中其他真实树木往往未标注，训练时会被当成背景；
2. 网络图片与香港街景存在域差异；
3. 测试集仅 57 个框，部分树种只有 1 个框；
4. 行道树互相遮挡、目标框较小，整图定位比预裁剪分类困难。
