## 数据格式核对结果

公开 README 对训练数据的描述是：PLY 点字段为 `[x, y, z, intensity, tree, label]`。真实数据还存在测试集特例：

- 训练轨迹 `00/1.ply` 含 6 个字段，`tree` 为 float64，`label` 为 int8。
- 测试轨迹 `02/1.ply` 只含 4 个 float64 几何与强度字段。
- `reference_data/02_1.npy` 为 int16，形状是 `(8876647, 2)`，行数与测试 PLY 点数严格一致。
- 参考数组样本第一列出现 8249 等实例编号，第二列出现 1 和背景值 -1，与 `[tree, label]` 语义吻合。

公开 README 只说明参考文件是 int16 真值，没有逐字声明两列顺序。因此读取器采用 `[tree, label]`，依据是字段语义、数值范围和逐行点数对应；这是当前最合理且已经过样本验证的解释。

## 实现内容

新增 `src/tscmdl_whu/io.py`：

- 解析 PLY 1.0 二进制小端头部。
- 支持常见 PLY 标量类型并构造无对齐结构化 dtype。
- 严格验证必需字段、顶点数、记录字节数和实际文件大小。
- 使用 `numpy.memmap` 映射 PLY 点记录，不整文件载入内存。
- 使用 `numpy.load(..., mmap_mode="r")` 映射 NPY 参考标签。
- 严格验证 NPY 为 int16、二维两列、行数等于 PLY 点数。
- 提供固定大小分块迭代、任意首尾范围读取和不足整块的末块处理。
- 统一暴露 `chunk.tree`、`chunk.label`、`chunk.intensity` 和按需复制的 `chunk.xyz()`。
- 提供上下文管理和显式关闭映射。

新增 `scripts/inspect_whu_trajectory.py`，用于对单条轨迹做有界检查并输出 JSON。新增 `tests/test_io.py`，使用临时微型 PLY/NPY 验证格式和边界，不依赖真实数据。

## 风险与限制

- 本阶段没有扫描所有 110 条轨迹的点负载，只对两个代表性格式做真实样本验证。中间位置的数据值异常不会被仅看头部和首尾样本的检查发现。
- PLY 内嵌 `tree` 使用 float64，而外置参考的 `tree` 使用 int16。读取器保留原始 dtype，不做隐式转换；A3 应在提取单树时显式校验整数性并转换。
- 当前读取器拒绝带有非 vertex 数据负载或 vertex list 属性的 PLY。这符合已检查的 WHU-STree 文件，但不是通用 PLY 解析器。
- `xyz()` 会为当前块创建连续的 N×3 数组，这是面向后续张量处理的显式局部复制，不会复制整条轨迹。
