# 何文田标注工具：点云辅助可行性方案

## 结论

可行。推荐先实现“同一目标树的交互式三维点云辅助窗”，再在获得或标定
Ladybug 相机与 LiDAR 的精确外参后实现逐像素点云投影。第一阶段已经能帮助
标注者判断树冠边界、遮挡和相邻树干扰，但不能把未经标定的点云覆盖层当作
像素级真值。

## 现有数据基础

- 何文田有 6,088 帧全景影像及逐帧 INS 平台位置、roll、pitch、heading。
- `pointcloud/ColorCloudPoint` 有 602 份二进制彩色 PCD，合计约 5.02 GB，
  通常每约 10 个影像序号一份；字段为 `x y z rgb`，单文件约 50 万点。
- `pointcloud/scans` 有 41,348 份带时间戳的原始扫描 PCD，合计约 7.25 GB。
- `pointcloud/mapping` 有五段稠密建图 PCD；单文件约 0.49–3.41 GB，不能在
  网页请求时直接读取。
- 点云局部坐标可通过固定原点 `(836613.637, 818490.840, 6.266)` 转为 HK80。
- 当前逐帧坐标仍是 INS/平台位置，尚未应用 Ladybug 光心杆臂与相机-LiDAR
  boresight 外参。

实测树 `RTR0121900` 时，与中间候选视图最接近的彩色点云文件在目标树平面
半径 5 m 内包含 7,912 个点，z 范围约 11.97–30.86 m，证明目标树点云确实
可从现有数据提取。两个侧向影像对应的最近彩色 PCD 未覆盖该树，因此不能
简单地“每张图只取最近的一个 PCD”；应先构建树级点云，再用三个相机姿态
观察同一份树级点云。

## 推荐架构

1. 建立彩色 PCD 空间索引
   - 一次性扫描 602 个文件，记录影像序号、点数和 XYZ 包围盒。
   - 原始 VMMS 文件只读，索引写入项目的 derived 目录。

2. 生成树级缓存
   - 查找包围盒与树点 5–8 m 圆柱相交的全部彩色 PCD。
   - 合并后进行体素去重、地面过滤和高度过滤。
   - 以树点为锚点进行聚类，保留目标簇及少量灰色上下文点。
   - 每棵树缓存约 20,000–100,000 个点，保留 RGB；输出紧凑二进制或 PLY，
     不在每次点击时重读 GB 级建图文件。

3. 增加后端接口
   - `GET /api/pointcloud/tree/{tree_id}` 返回缓存状态、点数、包围盒和文件 URL。
   - 首次未命中缓存时后台生成，前端显示“正在准备点云”；完成后自动刷新。
   - 缓存与人工标注使用同一个 tree ID，保证后续多模态训练能直接配对。

4. 增加前端三维辅助窗
   - 使用 Three.js/WebGL 渲染点云，支持旋转、缩放、点大小和 RGB/高度着色。
   - 点击“点云辅助”后在当前影像旁打开；切换三张影像时，只改变观察相机的
     位置和朝向，不改变目标树点云。
   - 默认相机使用该全景帧的 HK80 位置和姿态并朝向目标树，同时允许自由轨道
     观察，以便判断目标树、相邻树和遮挡。
   - 标注者可记录“点云可用 / 分割混杂 / 点云缺失 / 配准异常”。

5. 后续像素级投影
   - 获得 Ladybug 光心相对 INS 的杆臂、相机-LiDAR 旋转和平移、全景拼接模型
     后，把世界点变换到相机坐标并投影到等距柱状全景及当前裁剪。
   - 在这些外参未确认前，二维覆盖层只能作为可调试的近似结果，不能作为论文
     中“精确配准”的证据。

## 性能目标

- 已缓存树的点云加载时间低于 1 秒。
- 常规目标点数 20,000–100,000，桌面浏览器维持 30 FPS 以上。
- 首次树级缓存生成允许数秒，并显示明确进度；严禁在 HTTP 请求线程读取完整
  的 3 GB ASCII 建图 PCD。
- 先用不同距离、遮挡和树种的 20 棵树验收覆盖率、目标簇纯度和三视角一致性。

## 实施顺序

1. P0：生成 602 份彩色 PCD 的空间索引和覆盖率报告。
2. P1：实现树级裁剪缓存、后端接口和 Three.js 三维查看器。
3. P2：加入人工三维框/半径修正与点云质检状态，形成可靠多模态配对。
4. P3：补齐精确外参，增加点云到全景裁剪的二维投影叠加。
